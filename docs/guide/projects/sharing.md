# Sharing and project copies

Let people hear your work, keep a private draft, or start from someone else's project.

## Set the visibility

Your profile lists your public and private projects. The project's visibility control lets you change who can open it. Public projects let other people read the source and play the piece. A private project is for its owner; sending its URL does not make it public.

Give public projects a useful name, a short description, and relevant tags so people can find them. Add [README.md](readme.md) with playback instructions, credits, and links to related work.

## Share a link or player

Choose **Share Project**, then **Copy link**. For a public project, **Copy embed code** gives you a player to put on another website. Visitors still need to start playback, and the piece must work within that browser's audio and input permissions.

Try the public link while signed out before sending it. You will see the README and access the project as a visitor does.

## Make a fork

Choose **Fork Project** to create your own copy. Sign in if needed, then set the new project's name and visibility. A fork copies the saved project files; save edits and upload local results before forking if you want them included.

The new project belongs to you. Its attribution records where it came from, and edits to the copy do not change the source project. Keep the original author's credits and check the license before reusing samples or code.

## Keep a local backup

**Download Project (.zip)** exports the project files to your computer. For a newly generated audio or analysis result, also check the local file list and download or upload that result before leaving.

See [Files and saving](filesystem.md) for which changes live in the browser and which ones you have saved to the cloud.
